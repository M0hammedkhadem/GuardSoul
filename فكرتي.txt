أنت تعمل على تطبيق GuardSoul — تطبيق Android لحماية المحتوى الرقمي.
Stack: Kotlin · Jetpack Compose · MVVM + Clean Architecture · Hilt · Room · DataStore · AccessibilityService · VpnService · DevicePolicyManager

══════════════════════════════════════
 قواعد عمل صارمة (لا استثناء)
══════════════════════════════════════
1. الجودة قبل التقدم — لا تنتقل لميزة جديدة إلا بعد أن تعمل الميزة الحالية بشكل مثالي وبدون crash أو ANR.
2. المرجعية العالمية — ابنِ كل ميزة بمنطق مستوحى من أفضل تطبيق عالمي يقدم نفس الوظيفة بدقة، لا تخترع من الصفر.
3. نظافة الكود — احذف الكود الميت والملفات غير المستخدمة فوراً عند اكتشافها.
4. محظور: GLOBAL_ACTION_HOME — يُخرج المستخدم للـ launcher بدل التنقل داخل التطبيق. استخدم دائماً navigation داخلية (performAction على العنصر المناسب).
5. Event-driven حصراً — لا polling. استخدم AccessibilityEvents فقط (TYPE_WINDOW_STATE_CHANGED + TYPE_WINDOW_CONTENT_CHANGED).
6. الحالة تُحفظ دائماً — Room للبيانات الدائمة، DataStore للإعدادات.

 الميزات (نفّذ بالترتيب)
══════════════════════════════════════

─────────────────────────────────────
1. Social Media Blocking
─────────────────────────────────────
المرجع: آلية Shortstop — viewId lookup مباشر بدون confidence scoring معقّد.
لكل تطبيق: زر Toggle مستقل (ON/OFF).

[ YouTube ]
خيار A — YT Full Block: يحظر فتح تطبيق YouTube كاملاً.
خيار B — Block YouTube Shorts:
  • اكتشاف: فيديو Shorts أو الدخول لتبويب Shorts.
  • الاستجابة: رجوع قسري لـ YouTube Home Feed (ليس للـ launcher) + Toast رسالة حظر.
  • الأسلوب: TYPE_WINDOW_CONTENT_CHANGED + viewId مباشر لعناصر Shorts.

[ Facebook ]
خيار A — FB Full Block: يحظر فتح التطبيق كاملاً.
خيار B — Block Facebook Reels:
  • اكتشاف: دخول Reel فردي أو قسم Reels.
  • الاستجابة: رجوع قسري لـ Facebook Home + Toast حظر.

[ Instagram ]
نفس منطق Facebook تماماً (Full Block / Block Reels).

[ Snapchat ] — Full Block فقط.
[ X (Twitter) ] — Full Block فقط.

─────────────────────────────────────
2. Uninstall Protection
─────────────────────────────────────
المرجع: آلية MDM وتطبيقات Parental Control.
- منع الوصول لصفحة إعدادات تطبيقنا من تطبيق Settings (اكتشاف عبر AccessibilityService → رجوع قسري).
- منع إزالة صلاحية Device Admin من الجهاز.
- منع تعطيل أو تغيير DNS الخاص بتطبيقنا.

─────────────────────────────────────
3. Blacklist / Whitelist
─────────────────────────────────────
المرجع: BlockSite وFreedom.
كل قائمة مقسّمة لثلاثة أقسام:
  • Keywords — كلمات تُراقَب على الشاشة.
  • Websites  — مواقع تُحظر.
  • Apps      — يعرض قائمة التطبيقات المثبتة في الجهاز للاختيار بسهولة.

Blacklist:
  - Apps: يمنع فتح التطبيق نهائياً.
  - Keywords: إذا ظهرت كلمة على الشاشة → رجوع قسري + Toast.
  - Websites: يمنع الوصول للموقع.
  - تأتي بقائمة keywords ومواقع افتراضية (default list) من أول تشغيل.

Whitelist:
  - أي تطبيق/كلمة/موقع فيها → يُعفى من جميع ميزات GuardSoul بدون استثناء.

─────────────────────────────────────
4. Delay Stop Duration
─────────────────────────────────────
إعداد واحد يختاره المستخدم، مُخزَّن في DataStore:
  [ بدون تأخير | يومان | 7 أيام | 15 يوماً | شهر ]

─────────────────────────────────────
5. الصفحة الرئيسية — Shield (الدرع)
─────────────────────────────────────
- زر الدرع: يُشغّل/يوقف جميع الميزات دفعة واحدة.

- آلية الإيقاف:
  1. المستخدم يطلب إيقاف الدرع.
  2. يبدأ عداد تنازلي بمدة "Delay Stop" المختارة (الدرع يبقى مفعّلاً خلال العد).
  3. زر "إلغاء": يُوقف العداد ويستمر الدرع كأن شيئاً لم يحدث.
  4. عند وصول العداد للصفر: يُسمح للمستخدم بإيقاف الدرع.

- أيقونة Days:
  - عداد تصاعدي لأيام الاستمرارية دون انقطاع.
  - يصفّر حال إيقاف الدرع.

- أيقونة Blocks:
  - عداد تراكمي لإجمالي عمليات الحظر.

- زر "وضع التجربة":
  - يُشغّل الميزات بدون قيد التأخير.
  - مستقل تماماً عن الدرع (الدرع له الأولوية دائماً).
  - الإيقاف فوري بدون انتظار.

─────────────────────────────────────
6. Porn Blocker (Safe Search)
─────────────────────────────────────
المرجع: AdGuard DNS Safe Search / CleanBrowsing.
- تفعيل SafeSearch على Google وYouTube وBing وغيرها عبر DNS أو VpnService.
- البحث عن محتوى إباحي أو قمار → لا نتائج تُعرض.
